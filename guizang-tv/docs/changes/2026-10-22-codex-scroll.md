# 修复后续消息停留在可视区域之外

- Change-Id: `guizang-tv-20261022-codex-scroll`
- 执行者：Codex。
- 授权：用户反馈语音文字能回填，但重新进入后点击发送没有看到新消息，继续排查并修复。
- 基线：`272c806b2c33edbb70f515de5f486e71990d4be2`。
- 来源：用户确认首次语音回填成功、电视实际 UI 树与截图、连接服务状态及本次实机测试。个人对话及截图仅本地保留。

## 问题与变化

电视 UI 文本和连接服务均已包含后续消息及完整回复，但聊天区域停留在第一条消息，后续内容在可视范围之外。原实现只更新 TextView，没有滚动聊天容器，造成发送似乎没有反应。

现在首次加载面板及自身发送成功后滚到最新内容；位于底部时跟随流式更新，向上阅读历史时不强制跟随。使用 scrollTo 而不是会转移焦点的 fullScroll，并校验页面代数和视图身份，避免旧面板的延迟任务作用于新面板。

更新 Codex 说明：本次设备的系统输入法语音回填已有用户确认，不能推广为全部小米电视兼容。历史记录不清空，不修改电脑配对、系统助手、启动/唤醒或壁纸逻辑。

## 验证

- 公开 Debug 构建与既有 21 项 Java 测试通过；私人 Release 构建通过。
- 私人 `3.2-codex-scroll-trial` / versionCode 13 保留数据安装成功。
- 重进后截图显示原有最后一条消息及回答；系统键盘输入后不自动发送，显式发送测试问题得到回复，截图确认新问题和回复可见且焦点保留在发送按钮。
- 关闭后用遥控器确认键再次进入，截图确认仍显示最新消息。
- 第一份重进测试在检测到用户正在接收回答时主动停止，没有打断回答。后续脚本仅按文本查找首页 Codex 入口失败，改用关闭时恢复的焦点及遥控器确认键继续验证；不把脚本失败计为产品故障或通过。
- 向上阅读时不跟随由更新前滚动状态判断；此次实机覆盖重进和发送后的自动滚动，未做长回答期间人工翻页测试。
- 不创建正式 Release。连接服务原有会话继续保留。
